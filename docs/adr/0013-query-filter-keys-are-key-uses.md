# Query keys in QueryClient filters are key uses

`frontend/feature-system-query-contract` reads TanStack Query call syntax with the Oxc parser (ADR-0004) instead of searching for the text `queryKey`. A `queryKey` property in the filter object passed to a QueryClient filter method, such as `invalidateQueries`, `refetchQueries`, `cancelQueries`, `resetQueries` or `removeQueries`, is a use of an existing key when its value is an expression such as a key-factory call. It is not a declaration of a new query. A `queryKey` whose value is an inline array literal still counts as a declaration, as does every `queryKey` outside those filters. We rejected treating every filter key as a use: that would let components and routes hard-code keys again, which the contract exists to prevent.
